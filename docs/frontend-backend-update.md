# Подтверждение почты и настройки моков

Регистрация проходит в два шага: email → письмо → новый пароль и его повтор.
Фронтенд обращается к `/api/v1/auth/register` только с email и обрабатывает
`202`, `409`, `429`, `503` и ошибки полей `422`. Повторная отправка использует
таймер из ответа API. Ссылка последнего успешно отправленного письма заменяет предыдущую.

Фрагмент `#verify-email=...` читается до первого рендера и удаляется из URL.
Токен остается только в памяти. В `history.state` остается лишь флаг,
позволяющий после обновления страницы предложить повторно открыть письмо.
Ни токен подтверждения, ни пароли в хранилища не записываются. После успешного
`POST /api/v1/auth/verify-email` сессия хранится в `sessionStorage`, как при обычном входе.

Настройки мока содержат таблицу общих заголовков и общую задержку.
Удаление всех строк и задержка `0` явно сбрасывают значения через PATCH.
Фронтенд проверяет имена HTTP-заголовков, запрещенные служебные имена,
повторы без учета регистра, Latin-1 и пробелы/табуляцию по краям значений.
Задержка складывается с задержкой эндпоинта, максимум — 60 000 мс.
Проверка ответа доступна только при `runtime_status=running` и запущенном моке.
Название и описание эндпоинта необязательны; очистка полей отправляет `null`.

## Проверки

Из каталога `frontend`:

```sh
npm ci
npm test
npm run build
npm run preview:email
```

Макет письма доступен на `http://localhost:8894`. В него подставлены тестовая
ссылка на локальный интерфейс и срок 30 минут. Предпросмотр не отправляет писем
и не создает аккаунт; тестовый токен не является действительным.

Из каталога `backend`:

```sh
poetry install --no-root --with test
poetry run pytest -q
```

Автотесты фронтенда проверяют регистрацию, таймеры, ошибки API, очистку URL,
восстановление после обновления, UTF-8-пароли, прежний вход, таблицу заголовков,
совместимость старых записей, очистку метаданных и ожидание runtime.
Backend-тесты проверяют одноразовые ссылки, замену и истечение токена,
письмо HTML/plain text, миграции, наследование заголовков и ограничение задержки.

Для приемки доставки нужны настроенный SMTP и доступ к тестовому ящику.
В настольном и мобильном почтовом клиенте проверьте, что письмо читается
с отключенными изображениями, кнопка открывает форму выбора пароля,
старый токен после повторной отправки не работает, использованный токен
показывает ошибку, а после сохранения пароля открывается рабочая область.
Проверка HTML в браузере не заменяет проверку в почтовых клиентах.

## Выкладка

Backend, runtime и фронтенд нужно обновлять вместе:

```sh
docker compose up --build -d frontend runtime_worker
```

Compose применит миграции через `db_init`. Для локальной работы в `.env`
задайте `FRONTEND_PUBLIC_URL=http://localhost:8893/`, для Dokploy — публичный
HTTPS-адрес обновленного интерфейса. Заполните `SMTP_USERNAME` и
`SMTP_PASSWORD` в Environment Dokploy. Без SMTP регистрация возвращает `503`,
вход в существующие аккаунты остается доступным.
