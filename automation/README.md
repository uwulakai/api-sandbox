# Jenkins для API Sandbox

Jenkins запускается сервисом `autotests` в том же корневом Compose, что и API Sandbox.
Он не подключается к Docker daemon и обращается к опубликованному API и адресам
`public_url` по HTTP(S). Перезапуск Jenkins не требует перезапуска API, но полный
`docker compose down` остановит весь стек и сохранит данные Jenkins в `jenkins_data`.

## Dokploy

1. Использовать основной `docker-compose.yml` корня репозитория в существующем
   Compose application. Отдельный Dokploy-проект для Jenkins создавать не нужно.
2. Задать переменные по корневому `.env.example`:

   ```dotenv
   API_BASE_URL=https://api.api-sandbox.merlant.xyz
   JENKINS_ADMIN_USER=admin
   JENKINS_ADMIN_PASSWORD=<длинный уникальный пароль>
   E2E_WAIT_SECONDS=90
   E2E_CRON=
   ```

   При включённом Isolated Deployments также задать `TRAEFIK_DOCKER_NETWORK`
   равной точному имени изолированной сети проекта из Preview Compose
   (для текущего стенда — `apisandbox-monolite-uw4fku`). Этот выбор применяется
   к API, mock gateway и Jenkins, чтобы события запуска/удаления mock-контейнеров
   не меняли сеть, через которую Traefik подключается к публичным сервисам.

3. Выполнить Deploy/redeploy основного Compose. Первичная сборка скачает Jenkins,
   плагины и Python-зависимости.
4. Создать DNS для Jenkins-домена, например `tests.api-sandbox.merlant.xyz`.
   В Dokploy назначить его сервису **`autotests`, порт `8080`**, HTTPS/Let's Encrypt.
   TLS завершается на Dokploy; внутри контейнер принимает HTTP.
5. Открыть домен, войти с заданными credentials. Job `api-sandbox-e2e` создаётся
   автоматически. Для корректных абсолютных ссылок задать свой домен в
   **Manage Jenkins → System → Jenkins URL**.

Без admin-пароля контейнер не запускается. Саморегистрация и анонимный доступ
закрыты; CSRF-защита включена. Аккаунт создаётся один раз на постоянном volume;
последующую смену пароля делать через Jenkins, не через env.
Это Jenkins для доверенного администратора и одного встроенного job,
не общий сервер для выполнения чужих Jenkinsfile. Порты Docker и агентский 50000
не открыты. Лучше дополнительно ограничить доступ к домену VPN/списком IP.

## Запуск и результаты

`api-sandbox-e2e → Build with Parameters`:

- `API_BASE_URL` — адрес control-plane API, без `/api/v1` (начальное значение из env).
- `E2E_WAIT_SECONDS` — ожидание готовности runtime.
- `SUITE=full` — все HTTP-сценарии с созданием тестовых данных.
- `SUITE=smoke` — четыре проверки доступности/отсутствия авторизации, без создания данных.

В сборке: **Console Output** — текущие логи; **Test Result** — тесты и ошибки;
**Artifacts** — `report.html`, JUnit, журналы и `resources.json`.
HTML можно скачать и открыть локально: ослаблять Jenkins CSP не требуется.
Полный прогон помечается неуспешным при сбое теста или очистки.
При недоступном API runner завершится ошибкой, а не будет бесконечно ждать.
Сохраняются последние 30 сборок; одновременные запуски запрещены.

Тестовые аккаунты остаются в БД, удаления аккаунта пока нет. Удаление моков и отзыв
токенов выполняются по возможности; при аварии проверять `resources.json`.
Подробности и границы проверок — [e2e/README.md](../e2e/README.md).

## Расписание

По умолчанию **выключено**. Для ежедневного full-прогона около 03:00 UTC:

```dotenv
E2E_CRON=H 3 * * *
```

Затем redeploy основного Compose. `H` выбирает стабильную минуту; JVM настроена на UTC.
Пустое значение отключает таймер. Таймер использует значения параметров по
умолчанию, включая `SUITE=full`. Изменения job/параметров/расписания через UI
перезаписываются при старте контейнера: источники конфигурации — env и файлы репозитория.
Для нового стенда сначала запустите smoke и full вручную.

Поддержка параметров и cron описана в [документации Jenkins Pipeline](https://www.jenkins.io/doc/book/pipeline/syntax/).
JUnit-публикация использует [Jenkins JUnit](https://www.jenkins.io/doc/pipeline/steps/junit/).

## Обновление и ограничения

Тесты и Pipeline встроены в Docker image; после изменения исходников нужен rebuild
этого Compose-проекта. Volume `jenkins_data` сохраняет аккаунт и историю; его не удалять.
Не хранить `.env` и отчёты с данными в Git.

В текущем окружении разработки Docker CLI/daemon недоступны, поэтому сборка образа,
запуск Jenkins, первичное создание job и прогон из его UI **ещё не проверены**.
Python-инструмент и live-прогон проверены отдельно; это не эквивалент проверки Jenkins.
Образ основан на LTS, плагины устанавливаются при сборке: после первого успешного
развёртывания стоит зафиксировать digest образа и версии плагинов для воспроизводимости.
